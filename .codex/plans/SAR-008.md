## Locked decisions (sign these off)

**D-A · `MoneyView` — the pure read-model shape (all money fields integer paise).**
```ts
interface MoneyView {
  localDate: string; monthStart: string; monthEnd: string; daysLeftInMonth: number;
  headline: { netPaise: number; creditPaise: number; debitPaise: number };   // this-month sums
  safeToSpend: { valuePaise: number; balancePaise: number;
                 remainingBudgetedPaise: number; upcomingRecurringPaise: number }; // the glass-box 3 terms
  budgets: MoneyBudgetBar[];        // {budgetId, categoryId, categoryName, limitPaise, spentPaise,
                                    //  percentUsed /*int floor*/, status: 'ok'|'warn'|'over'}
  recurringShelf: MoneyRecurringChip[]; // {id, direction, amountPaise, label, nextPostDate, postedThisMonth}
  days: MoneyDayGroup[];            // month window, desc; {localDate, label /*'Today'|'Yesterday'|date*/,
                                    //  netPaise, rows: MoneyEntryRow[]}
  drills: MoneyCategoryDrill[];     // per category incl. 'uncategorized': {key, name, rows, spentPaise, bar: MoneyBudgetBar|null}
}
```
`MoneyEntryRow = {id, title /*merchant ?? note ?? categoryName ?? 'Transaction'*/, categoryKey, categoryName, direction, amountPaise, estimated, recurring /*recurringRuleId != null*/}`. `buildMoneyView({localDate, transactions, categories, budgets, recurringRules})` is deterministic and computes drills in core so the lens stays logic-free (the `TodayBody` convention). `formatPaise(paise)` renders ₹ via integer divmod + en-IN grouping; paise shown only when non-zero. Ledger + headline window = the current month (rollover summary deferred).

**D-B · Balance is DERIVED — headline = this-month net; no account concept.** There is no account/balance table and invariant #7 forbids inventing one. Headline (SCREEN-LENSES §1a "₹ 41,250 this month") = `creditPaise − debitPaise` over the month window. **Safe-to-spend (pinned formula, all integer paise):**
```
balancePaise            = Σ credits(month, ≤ localDate) − Σ debits(month, ≤ localDate)
remainingBudgetedPaise  = Σ over active budgets (periodStart ≤ localDate ≤ periodEnd):
                            max(0, limitPaise − spentInPeriodPaise)      // spent = Σ debits in category within the period
upcomingRecurringPaise  = Σ over rules (isPaused=false, direction=debit,
                            localDate < nextPostDate ≤ monthEnd,
                            NOT (categoryId covered by an active budget)):  amountPaise   // dedupe — no double subtraction
safeToSpendPaise        = balancePaise − remainingBudgetedPaise − upcomingRecurringPaise
```
Debits-only in the recurring term (upcoming income never pre-counts — ask-don't-invent posture); the budget-overlap dedupe prevents Rent-style double subtraction; negative safe-to-spend renders honestly in plain ink (statuses stay budget-bar-only). The long-press math sheet shows exactly these three terms + the result. *(Vetoable: drop the dedupe for spec-literal subtraction of both terms.)*

**D-C · Nullable `categoryId` → an explicit `'uncategorized'` bucket.** Ledger rows with `categoryId:null` render an "Uncategorized" chip; category totals and the drill list include the bucket; it can never have a budget bar (`budgets.categoryId` NOT NULL) and never joins the safe-to-spend budget term.

**D-D · Budget bar status thresholds:** `spent > limit → 'over'` (`--danger`) · else `percentUsed ≥ 90 → 'warn'` (`--warn`) · else `'ok'`; `percentUsed = floor(spent*100/limit)` integer math; bar fill = `min(percentUsed,100)`. These are the **only** status colors in the lens; income rows use `--ok`; everything else is ink/honey tokens.

**D-E · Lens = read-only display + local drill state.** `MoneyLens.tsx` is `"use client"` (drill + math-sheet state), rendering: header (domain caption + headline Display + coach-read slot omitted this ticket — no fast-tier call) → safe-to-spend hero (long-press/click ⇒ math sheet disclosure) → budget bars (tap ⇒ drill) → recurring shelf chips (display-only ↑/↓ + next date; pause/edit deferred) → day-grouped ledger obeying the shared row grammar (domain tick · title · category chip · tabular amount right, credits in `--ok`, `~` on estimates). **Drill = in-lens push/return**: tapping a bar/category swaps to that category's `MoneyCategoryDrill` (its bar + rows) with a back affordance; state resets on domain switch. Day-1/empty states per SCREEN-LENSES §1b ("Set budgets" chip is a dead affordance label this ticket — E5 resume is onboarding's). No `+` form — capture is the only add path.

**D-F · Dev seed gains a deterministic money slice** (dev-only; not the judge seed): categories — Food & dining (exists), Transport, Rent (expense), Salary (income); ~6 transactions across today/yesterday incl. one `estimated:true`, one credit, one `categoryId:null`; budgets — Food ≈78% and Transport >90% (one warn bar in shots); rules — Salary ↑ (posted, credit), Rent ↓ + Spotify ↓ upcoming before month-end. Amounts chosen so `safeToSpendPaise` is positive and hand-checkable.
