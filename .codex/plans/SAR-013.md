## Outcome

The capture launcher records a bounded clip through the browser media API, submits it only to
`VoiceProvider`, then pins the returned transcript in the capture sheet before parsing. The fake
stack remains deterministic and keyless. A transcription failure leaves the same ephemeral audio
draft open and retryable; it persists no outbox entry, typed row, commit, XP, or plan effect.
Text and photo capture retain their existing behaviour; voice joins the exact existing
parse → route → typed-commit path only after transcription succeeds.

## Non-negotiable boundaries

- **No real voice adapter or key.** Do not implement Sarvam, Gemini, OpenAI, or Web Speech. The
  existing fake provider is the only callable adapter. A selected unimplemented provider continues
  to fail explicitly and safely.
- **30 seconds is a hard transport cap.** `30_000` is a behavioural integer limit. The recorder
  force-stops at the cap before upload and the server-side transcription service independently
  rejects a declared duration outside `1..30_000` before it invokes `VoiceProvider`.
- **No write before parse/commit.** Transcription has no repository dependency. Failure/retry is
  in-memory only; no automatic queue, outbox, commit, XP, or typed persistence is allowed.
- **Provider-blind and core-clean.** The transcription result/service accepts an injected
  `VoiceProvider`; no provider implementation or framework import enters `core/`.
- **Same capture seam.** Once the user confirms the pinned transcript, voice calls the existing
  parse endpoint and the existing `ingestDraft` / `routeDraft` / commit flow. It must be identified
  as `source: 'voice'` with its STT confidence; server-owned capture metadata overrides any LLM
  transport metadata. Text defaults to `source: 'text'` and remains otherwise byte-for-byte
  behaviourally equivalent.
- **Do not touch the pending `.gitignore` diff.** It is unrelated, deliberately unstaged, and must
  not be reverted, staged, or included in the SAR-013 diff.

## Build shape

1. **Core transcription seam**
   - Add a framework-clean, typed transcription service under `core/voice/` (or an equivalently
     isolated core module) with an injected `VoiceProvider`, a typed success/retryable outcome, and
     the shared `30_000` duration policy.
   - It validates the audio MIME type and integer duration before calling the provider, catches
     provider errors as retryable, and has no persistence imports or side effects.
   - Extend the parse input only as needed for server-owned transport metadata: `source` and
     `transcriptConfidenceBps`. After the gateway object validates, retain its proposals/questions
     but overwrite raw transcript, capture time, timezone, source, and STT confidence with the
     trusted parse input. Do not change route-by-confidence rules.

2. **Transcription route and client transport**
   - Add `POST /api/capture/transcribe`: multipart audio plus MIME/duration fields, exact
     validation, `getSession().voice`, and a JSON typed transcription outcome. It never calls the
     LLM, repository, commit service, or a provider SDK directly.
   - Add a client `transcribeVoice` wrapper using `FormData` and the current safe-fetch posture.
     It returns a safe retryable result on network/non-JSON failure.
   - Update the parse route/client so voice passes trusted intent metadata and text preserves its
     existing default path. Do not create a parallel voice parser.

3. **PTT and transcript sheet**
   - Replace the launcher’s placeholder mic action with a client-side `MediaRecorder` state machine:
     hold starts and release stops; a quick tap enters tap-to-toggle and the next tap stops; cancel
     discards the ephemeral clip; all stream tracks stop in every exit path.
   - Show recording/toggle state, elapsed duration, a 30-second ceiling, and accessible labels. Use
     existing tokens/classes only; the duration is behavioural, not a visual style constant.
   - Extend `CaptureInput` / `CaptureSheet` with a voice-audio path. The sheet owns transcribing,
     retrying the same in-memory clip, a visibly pinned/editable transcript, confidence treatment,
     and an explicit Parse control. Low-confidence wording is editable before parse.
   - The provider/network-failure state stays open with `Retry` and a safe dismiss/re-record path.
     A duration rejection explains that a shorter recording is required. No error state may create a
     database mutation.

4. **Fake stack, tests, and visual evidence**
   - Keep `FakeVoiceProvider` deterministic and fetch-free. Test a valid fake clip, rejected
     over-limit clip without provider invocation, throwing provider → retryable zero-side-effect
     outcome, and no live adapter/key wiring.
   - Test parse metadata ownership for text and voice without changing F3’s routing or
     `wrongSilentWrites === 0` invariant.
   - Extend screenshot automation with `SHOTS=voice`: 390px Ember dark/light for recording,
     pinned transcript, provider-failure/retry, and post-parse confirmation; add Ember-dark desktop
     correctness smoke. Mock browser media primitives in the harness, never production code.

## Acceptance and verification

- Press-and-hold and tap-to-toggle both record bounded audio; every valid clip reaches only the
  `VoiceProvider` port and fake stays keyless/deterministic.
- The `30_000` ms cap is enforced before provider upload on client and at the server seam.
- Provider/network error retains a retryable open audio draft and produces zero outbox, typed rows,
  commits, XP, or plan effects.
- The transcript is visibly pinned and editable before parsing. Voice then follows the existing F3
  route/commit behaviour; ordinary text capture is unchanged.
- Run, in order: `pnpm check`, `pnpm build`, `.codex/hooks/check-invariants.sh`, then seed a fresh
  populated local DB and run the `SHOTS=voice` screenshot pass on a new port. Sol must review the
  rendered evidence under D-041 before this ticket is accepted or committed.
