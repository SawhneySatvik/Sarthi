## Outcome

Replace the Coach, Stats, and Journey placeholders with one calm, data-backed reading
room, a collectible-but-auditable stats wall, and an evidence-first memory timeline. The
screens consume only the authenticated repository scope and framework-clean pure view
models over existing typed rows. The only writes are the already-signed Coach API actions:
on-open brief generation/retry, session-only Ask, and the visible Adaptation Keep/Revert
actions. Stats and Journey are read-only.

**Design read:** a quiet editorial life-app for a person reviewing their own progress;
low-density, text-forward, `Fraunces` only for coach voice, with restrained collectible
motion and zero dashboard/card-grid drift. The existing Sarthi token system is the design
system; no new dependency, font, raw visual value, or generated art asset is introduced.

## Locked interpretations and boundaries

- **Potential is honest, not fabricated.** The signed schema has no persisted daily
  projection/cache contract. SAR-015 therefore implements the documented unavailable state:
  the Potential face falls back to the live value with an explicit `not enough data` label.
  It must never invent the P6 example numbers or cache arbitrary client data. A real
  deep-tier, daily-cached projection requires a separately signed persistence contract and
  ticket; it is not silently added here.
- **On-open brief generation is permitted; plan mutation is not.** The Coach client calls
  `POST /api/coach/brief` only to generate/reuse its staleness-keyed daily note and, on a
  local Sunday evening, its weekly note. It keeps the last successful note visible on
  failure and exposes a quiet retry. It never writes a plan, profile gap answer, capture,
  XP, or ad-hoc chat row.
- **F9 remains glass-box.** A normal read only uses the pure re-entry lookup. A root-app
  launch that is re-entry eligible redirects once to `/coach?reentry=1`; the Coach client
  then explicitly calls the existing `propose-reentry` action and presents the resulting
  proposal. That action creates a visible `adaptations.proposed` row only — no plan row
  changes until the user presses **Keep**. Repeated opens reuse the same adaptation episode.
- **Ask is session-only.** The composer keeps its visible question/answer thread in client
  state for the current tab visit. Text and a VoiceProvider-backed microphone transcription
  both populate the composer; a separate deliberate Send calls `/api/coach/ask`. It does
  not parse a capture, create an outbox, or persist a message row. Voice failure preserves
  the text/draft and offers retry, with no write.
- **Journey uses real evidence rows, not generic event storage.** Seeded image evidence may
  use the documented gradient placeholder while local binary storage is not available; the
  card and viewer retain its typed evidence caption/domain/date and `View entry` routes to
  the matching Today lens. No fake remote URL, image persistence system, or generic timeline
  table is introduced.
- **No unrelated work.** Do not touch the user-held `.gitignore` diff, provider wiring,
  auth/billing, tools, arbitrary chat persistence, a projection schema, or photo/audio
  storage. Keep all new pure transformations inside `core/` framework-import-clean.

## Build shape

1. **Typed, pure screen read models**
   - Add framework-clean reader modules under the existing `core/coach/` and `core/game/`
     boundaries (exported through their existing barrels). Their inputs are only typed
     repository DTOs plus an explicit local date/time; they import no React, Next, driver,
     provider implementation, or clock.
   - `buildCoachReadingView` deterministically selects the current daily ritual note, latest
     weekly note, reverse-chronological collapsed history, first open profile gap, concrete
     adaptation summaries (`before → after + reason + status`), and evidence counts. It keeps
     daily prose distinct from the rich weekly card and never treats a proposed adaptation as
     an applied Today change.
   - `buildStatsView` projects existing `domain_progress`, day-one snapshots, active arc,
     plan rows, and domain read models into Overall plus the four locked domain cards. Health
     uses real plan adherence, Money reuses the integer `formatPaise`/safe-to-spend read
     model, Habits uses its real best streak, and Skills uses the integer `H:MM` mastery
     formatter. Day-1 is the immutable snapshot delta; a missing snapshot is explicitly
     unavailable, not zeroed or manufactured. All cards carry a semantic text equivalent for
     sparklines.
   - `buildJourneyView` groups `evidence` rows by local date, joins only matching typed
     CoachNotes when present, and derives deterministic milestones from actual progress,
     completed arcs, skill-mastery thresholds, and streak records. It emits stable
     reverse-chronological day groups, month separators, text-only nodes, and multi-photo
     groups without creating a log/event table or double-counting a threshold.
   - Add keyless unit tests for ordering, no-data/Day-1 fallbacks, integer display inputs,
     evidence-domain grouping, milestone de-duplication, and the invariant that an
     `adaptations.proposed` item is presented as pending rather than as a changed plan.

2. **Authenticated server readers and narrow navigation seams**
   - Replace the three stub pages with dynamic server pages following the established
     `/today` composition pattern: call `getSession()`, read only the already-bound
     repositories in parallel, build the pure view model, and hand serializable props to
     client leaves. No page accepts or forwards a `userId`.
   - Read all history required by the view in memory for v1 (notes, adaptations, gaps,
     day-one snapshots, progress, arcs/items, typed domain rows, and evidence). Preserve the
     repository's scope; pages must not query driver tables directly or add an unscoped filter.
   - Make `/` perform the F9 launch decision before its normal `/today` redirect: if the
     pure game summary is re-entry eligible, send the launch to `/coach?reentry=1`; otherwise
     preserve `/today`. Direct tab links do not cause surprise navigation.
   - Add the minimal `?domain=health|money|habits|skills` initial selection seam to Today’s
     existing `DomainSwitcher`/`TodayBody`. Stats card taps and Journey’s `View entry` use it
     to reach the already-built lens; invalid/missing parameters remain the All spine. This
     is navigation only — it does not duplicate a lens or add entry-detail persistence.

3. **Coach reading room and safe client actions**
   - Add `components/coach/` client leaves for the reading room, brief lifecycle, adaptable
     sheet, history rows, and Ask composer; retain the page itself as the server data reader.
     The reading column is `~620px` on desktop, canvas-backed and prose-led; only the weekly
     note receives the full card, painterly-band treatment. Use existing UI primitives and
     Sarthi semantic tokens only.
   - Render the morning plan/evening recap from the current daily note, an inline open-gap
     chip group, adaptation chips below the prose, rich weekly domain lines plus evidence
     footer, and accessible in-place daily/weekly history expansion with month separators.
     Map only the existing `detail-*` gap keys to their matching, already-validated
     `OnboardingDetailInput` form/chips and submit them to `/api/onboarding/detail`; the
     inline state settles into prose only after that typed server write returns `ok` and the
     refreshed gap is `answered`. A multi-field DETAIL answer may expand its minimal inline
     sub-form (for example food pattern plus cooking), rather than inventing a one-value
     generic profile patch. Unknown `goal-*` gaps remain a prompt/link, never a fabricated
     answer or a locally closed chip.
   - Adaptation sheet actions send only `{ action, adaptationId }` to the existing route.
     Keep/Revert disable while pending, retain the sheet/error state on failure, then refresh
     server data after success. The client never sends snapshots, a plan patch, or a user id.
   - On `?reentry=1`, use the existing explicit `{ action: "propose-reentry", localDate }`
     API exactly once per mounted launch when the server model is eligible and has no existing
     lifecycle. Surface the returned proposed adaptation in the sheet/chip; proposal failure
     is quiet and leaves all server data unchanged.
   - The Ask composer uses the existing `usePressToTalk` + `transcribeVoice` boundary and its
     30-second cap. A successful transcript is visible/editable in the ask field before Send;
     only Send posts `{ text, timezone }` to `/api/coach/ask`. Stream-like UI is a local
     pending/skeleton state around the existing non-streaming endpoint, not a new streaming
     protocol. Action chips may open an existing proposed adaptation; they cannot author one.

4. **Stats and Journey client surfaces**
   - Add `components/stats/` for the Current / Potential / Day-1 segmented control and
     accessible card faces. Current is the default; cards flip with the existing motion
     dependency while `prefers-reduced-motion` crossfades. The Overall earned card alone may
     use `--energy`; base level/streak values stay neutral per D-041. Domain sheen is a
     low-opacity token-derived decorative layer, never a hardcoded color or a second card.
   - Card tap navigates to the appropriate Today lens. Potential carries a visible
     `projected` tag only when a future signed projection exists; this ticket’s unavailable
     fallback must instead say `not enough data` and not look like a fact. Day-1 renders
     `then → now` only from the immutable snapshot.
   - Add `components/journey/` for the continuous rail, day nodes, milestone diamonds,
     evidence cards, collapsed multi-photo day rows, sticky month separators, and a
     keyboard-operable full-screen viewer. A `fake`/missing image uses the locked gradient
     placeholder with the real caption/alt text; `View entry` sends the user to the typed
     domain lens. Text-only days remain nodes only.
   - Keep motion restricted to the documented stats flip/desktop tilt and earned milestone
     feedback; honour reduced-motion and provide textual equivalents for sparklines, rail,
     image captions, and all controls. Do not use emoji glyphs or add a second icon family.

5. **Demo data, screenshot harness, and verification**
   - Extend the reset-only populated dev/demo fixture enough to demonstrate these read models:
     immutable Day-1 snapshots; a daily and a rich weekly CoachNote; one safe proposed
     adaptation; typed evidence distributed across the twelve-day demo window; and real
     typed progress/plan/session rows sufficient for meaningful Card and Journey states.
     Preserve all integer units and the `seed_runs` idempotency/tenant boundary. The fixture
     may not create generic timeline data or mutate a real user's rows outside `seedDemo`.
   - Extend `scripts/screenshot.mjs` with a `SHOTS=coach` pass covering Coach daily/weekly,
     sheet, Ask answer, Stats Current/Day-1/Potential-unavailable, and Journey rail,
     multi-photo expansion, and viewer. Capture required 390px fidelity shots and desktop
     smoke shots in Ember Dark + Light; also sweep Stats through Bone/Moss once, as its spec
     requires. Save all evidence under `.verify/screens/`.
   - Test client-facing action contracts without network keys (brief retry presentation, Ask
     no-write failure, Adaptation payload shape, initial-domain navigation), then run
     `pnpm check`, `pnpm build`, `.codex/hooks/check-invariants.sh`, and `git diff --check`.
     Run `pnpm screenshots` against a freshly reset keyless SQLite demo on a fresh port, then
     Sol performs the D-041 rendered review. Mobile 390 fixes block acceptance; desktop blocks
     only correctness/regression under D-034. Re-run every changed shot after any visual fix.

## Acceptance and verification

- **P5:** Coach reads as a 620px editorial page with generous coach leading; the adaptation
  sheet exposes exact before/after/reason and only Keep changes Today; the weekly brief is
  visibly the richest object.
- **P6:** Stats is collectible but calm: subtle domain sheen, earned-only amber Overall,
  Current/Day-1 semantic state, and a reduced-motion-safe flip. A missing prediction says
  `not enough data`; a future value can never be visually mistaken for a current fact.
- **P7:** Journey scrolls as memory rather than a generic log: continuous rail, real typed
  evidence/captions, sparse text-only nodes, distinct milestone punctuation, expandable
  multi-photo days, and an accessible viewer/lens hand-off.
- **Flows:** F6 Keep changes tomorrow only through the existing commit path; F7 shows weekly
  evidence and the Day-1 reflection; F9 produces a visible proposal without a silent plan
  write; F11 has working Coach, Stats, and Journey shots 6–8 and 10 on the fake stack.
- **Safety:** no estimate/capture/plan/profile/chat write is added outside the signed routes;
  every number derives from a typed row or immutable snapshot; money/quantity math remains
  integer-only; `core/` remains framework-import-clean; keyless fake remains complete.

## Handoff to Terra

Build in this order: pure readers + tests → server page composition and Today lens hand-off →
Coach action leaves → Stats/Journey surfaces → deterministic demo fixture and screenshot runner
→ targeted tests and full verification. Do not implement real projection storage, background
scheduling, arbitrary chat persistence, a new provider, image storage, or an unapproved F9
plan write. Stop and report if the view cannot be built from the existing typed contracts, if a
requested interaction needs an unapproved write route, or if token-only styling would require a
new signed token rather than an existing semantic token.
