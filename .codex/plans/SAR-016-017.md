## Outcome

Replace the Tools and Settings placeholders with two real, quiet product surfaces.
Focus and Meditation complete only through explicit, idempotent typed commits and
use the existing five-minute latest-batch Undo seam. Settings moves the current
temporary theme pill into the avatar sheet, makes theme previews real token
renders, and exposes a session-scoped, server-authorised runtime-provider override
only in local development or an explicitly enabled judge environment.

This combines implementation and visual review only. **SAR-016 and SAR-017 retain
their own acceptance criteria and gates:** SAR-016 moves F8 and `timer-session`;
SAR-017 moves F10 and F11 shot 9. Neither ticket is marked landed until its own
acceptance and screenshot states pass.

## Locked interpretations and boundaries

- **Tools use a typed command, never a fake capture.** A completed Focus run creates
  exactly one `skillSession` with `source: 'timer'`; Meditation creates exactly one
  `habitLog` with `source: 'tool'`. Both are explicit, integer-minute records,
  `estimated: false`, `confidenceBps: 10000`, and use a stable client-created
  idempotency key for retry. The server owns the scoped entity lookup, local date,
  and final Zod validation; a client never supplies `userId` or a row payload.
- **The initial Meditation habit joins the same reversible batch.** If consented
  Meditation has no active `Meditate` habit, the typed command creates that one
  `Habit` and its `HabitLog` in the same transaction and records both in
  `commit_rows`. Undo removes the log first, then the newly-created habit. An
  existing habit is never altered or deleted by the tool undo.
- **Consent comes before the first tracked meditation run.** F8 is the governing
  journey: a first-use consent sheet appears before Start. Declining returns to
  idle and writes nothing; accepting permits the run and only then enables its
  eventual typed completion. This resolves the screen prose's ambiguous
  complete-time wording in the safer direction.
- **A timer start is not a write.** `sessionStorage` holds a live Focus/Meditation
  run for the browser session and an app-layout provider renders the resume ribbon
  above navigation. Natural completion submits the selected whole-minute duration;
  abandon requires an explicit `Log X min` or `Discard`, where `X` is measured,
  floored to a positive integer minute. Discard writes nothing. Replaying a
  completion returns its original commit rather than creating another session/XP.
- **Creating a skill is an explicit setup action.** The Focus selector defaults to
  the most-recent active scoped skill. `+ new` opens a minimal named-skill sheet
  and creates the `Skill` before the run starts; it is not disguised as a timer
  completion or capture proposal. A missing/foreign skill id fails server-side
  before a commit starts.
- **No real runtime key is wired.** Fake remains the deterministic default. The
  provider selector may select only an allowed, verified LLM provider for the
  current client session; Anthropic stays visibly unavailable because the signed
  matrix has no verified runtime model id. A missing real-provider key produces
  the existing retryable provider failure and no typed write.
- **Provider override is header-scoped, not an env mutation or cookie.** In a
  development build or `JUDGE_MODE=true`, the client stores the selected provider
  only in React memory and sends a strict allowlisted header to runtime AI routes.
  Each route resolves it after the authenticated session and passes it to the
  provider factory for that request. A reload restores the environment default.
  Public production ignores the header and omits the entire Developer section;
  there is no hidden gesture and no client-settable environment selector.
- **Settings does not invent a persistence schema.** Theme/mode use the existing
  profile columns plus local storage (with `system` resolved to a concrete stored
  mode). Existing DETAIL/profile-gap answers reuse their signed onboarding route.
  Mic/TTS/brief preferences are local-session/local-storage preferences on the
  keyless track until a signed profile-preferences contract exists; they must not
  be represented as fabricated profile columns or affect a production provider.
  Export is a scoped JSON serializer. Destructive actions remain confirmation-first
  and are implemented only where a typed, scoped operation is available; no generic
  delete endpoint, driver access, or misleading success state is allowed.
- **No adjacent expansion.** Do not build Afford-it, Workout Counter, payment/auth,
  a generic activity table, background timing, notifications, TTS provider keys,
  persistent feedback, or a production provider-toggle gesture. Do not touch the
  user-owned `.gitignore` change.

## Build shape

1. **Framework-clean typed Tools core and commit extension**
   - Add `core/tools/` contract/service/view modules and export only framework-clean
     types/functions. The view reads scoped `Skill`, `SkillSession`, `Habit`,
     `HabitLog`, current plan rows, and integer progress to produce serializable
     Focus/Meditation context; it does not import React, Next, a driver, or a
     provider implementation.
   - Refine `CommitInput` into an exhaustive, discriminated tool form rather than
     adding a table/payload escape hatch. The `focus` form permits only an accepted
     `skillSession` with `timer` source; the `meditation` form permits only an
     accepted `habitLog` with `tool` source and, when consented, the typed
     `Meditate` habit setup. Extend the existing snapshot/undo map for `habit` and
     preserve reverse-order removal. Existing capture/tap/edit behaviour is
     unchanged and keeps `source: 'capture'`.
   - Add scoped server routes for explicit new-skill setup, Focus completion, and
     Meditation completion. Validate names, UUIDs, positive integer minutes,
     timezones, pattern ids, consent state, and idempotency keys at the boundary;
     build resolved proposals server-side and call the shared commit service. Route
     failures leave the client run retryable and create no typed row.
   - Unit-test new/existing Meditation branches, stable idempotent replay, foreign
     ids, invalid/float/zero minutes, no write on discard/declined consent, source
     attribution, progress/Today effects, and full undo including first-use habit
     removal. Add the `timer-session` fake fixture to the eval harness.

2. **Tools shell, live loops, and capture hand-off**
   - Replace `/tools` with an authenticated server reader over the bound repository
     scope, then render a client `ToolsDesk` plus an app-layout `ToolsProvider` / resume
     ribbon. No page or component receives a user id.
   - Build the two-column mobile / three-column desktop bento with Focus as the
     tall violet anchor, Meditation indigo, Afford-it and Workout at 60% with a
     quiet `soon` toast, and a session-only Suggest card that persists nothing.
     Domain ticks make each real target store visible; cards and sheets meet the
     documented 44px/a11y/reduced-motion rules.
   - Focus sheet: durations 25/50/90/custom, required scoped skill selector,
     explicit new-skill mini-sheet, tabular countdown, mastery `H:MM → target`
     caption, start/resume, natural complete, abandon Log/Discard branch, violet
     completion/Undo strip, and `+ note?` opening the existing capture sheet with
     a visible text frame. The note is still parsed and committed by the normal F3
     path—no hidden note or second tool write.
   - Meditation sheet: Box/4-7-8/5m/10m patterns, first-use consent, phase-driven
     breath circle with a Fraunces phase label, timer, optional local TTS setting
     (off default), opacity-only reduced-motion fallback, indigo completion/Undo
     strip, and Today refresh after a successful commit.

3. **Settings sheet, real themes, and authorised override**
   - Replace the temporary fixed `ThemeSwitcher` pill with an avatar-triggered,
     keyboard-operable full-height `SettingsSheet` mounted from the authenticated
     app shell. On desktop it is the specified centered quiet panel; Settings is
     never added as a sixth tab.
   - Extract/reuse the token application logic from onboarding so Appearance has
     three genuine mini-Today token previews plus Light/Dark/System control. A
     selection crossfades the app behind the sheet, writes `sarthi-theme`, and
     best-effort persists the existing profile theme columns via a narrow typed
     route; it never hardcodes a preview palette.
   - Render real grouped rows for identity, supported onboarding-detail/profile-gap
     editing, display units, mic/TTS and on-open-brief local preferences, Coach
     schedule labels, JSON export, guarded Data confirmation views, About, and the
     correct Local mode/sign-out footer. Unsupported destructive operations must
     stop at an honest unavailable state after typed confirmation rather than
     pretending rows were deleted; the implemented export is strictly repository
     scoped and contains typed tables/profile only.
   - Add a `Developer` disclosure only when `isDeveloperControlAllowed` is true.
     It shows the active LLM tier map from `LLM_MODEL_MATRIX`, strictly allowlisted
     AI/voice choices, and the existing authenticated idempotent seed action. The
     LLM selection lives in client context and is attached only to applicable
     capture/coach requests; route-level runtime resolution rejects it in public
     production. No new API key, env write, or persisted provider preference is
     introduced.

4. **Fixture, screenshot, and verification gates**
   - Extend the deterministic populated seed only as needed for the tool selector,
     Meditation existing-habit branch, and visible plan completion. Do not add a
     generic tool/event record or change seed idempotency.
   - Extend `scripts/screenshot.mjs` with `SHOTS=tools` and `SHOTS=settings`:
     Tools grid, Focus idle/running/complete/abandon/resume, Meditation
     consent/running/complete, coming-soon toast, suggestion flip; Settings main,
     real theme previews/mode, detail consequence/gap queue, developer tier map /
     override caption, and danger typed-confirm state. Capture 390px fidelity and
     desktop smoke in Ember Dark/Light; Settings also receives the six-mode sweep
     required by its screen contract. Keep screenshot-only state controls dev/judge
     gated and absent from public production.
   - Add focused core/API/view tests, then run `pnpm check`, `pnpm build`,
     `.codex/hooks/check-invariants.sh`, and `git diff --check`. Use a reset
     keyless SQLite fixture on a fresh port for screenshots. Sol performs D-041
     rendered review; mobile deviations block, desktop blocks regressions only.

## Acceptance and verification

- **SAR-016 / P8 / F8:** Grid is full but calm; both live tools complete their
  declared loop; ticks visibly match Skills/Habits; Focus files one timer session
  and Meditation writes only after consent; each commit is idempotent and latest-
  batch undo reverses its typed rows, XP, plan effects, and first-use habit setup.
- **SAR-017 / P9 / F10/F11 shot 9:** Theme previews are actual token renders and
  apply live; avatar opens the quiet Settings sheet; the Developer row is visible
  only in local/judge scope and its tier caption derives from the matrix; public
  production cannot reveal or honour an override; data-danger controls require an
  intentional confirmation and never claim a write they did not make.
- **Global:** Keyless fake stack stays complete; estimate safety and integer units
  hold; all mutations use the authenticated scoped repository and typed commit
  seam; `core/` stays framework-import-clean; no raw colour/radius/duration enters
  components; amber remains restricted to earned XP/streak/level.
