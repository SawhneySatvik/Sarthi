## Outcome

Make the already-landed vertical slices behave as one uninterrupted, keyless
product: each F11 shot starts from a real route, follows the one typed capture
and commit path, and visibly lands in the relevant view. At the same time, ship
the approved painterly illustration system as optimized static art, with one
registry and purposeful emotional placements—not decorative data-surface noise.

This ticket repairs integration seams only. It does **not** add a domain, generic
activity/event storage, a second capture/write route, real provider keys,
auth/billing, or a new screen. `SAR-019` remains the exhaustive six-mode
token/screenshot sweep; `SAR-020` remains the eval report and formal F11 dry-run.

## Locked decisions and boundaries

- **The user-approved art scope is complete but restrained.** Integrate every
  supplied scene through the ART registry: Today time-of-day headers and
  rest/all-done states; typed-plan/habit contextual art; Tools bento and Focus
  detail; onboarding phases; Journey milestones; and the Coach weekly band.
  Capture cards, typed lens data zones, Stats, and Settings remain art-free.
  An illustration never replaces a number, confidence state, capture card, or
  typed evidence record.
- **Ship WebP derivatives, not 68 MB PNG sources.** `assets/images/` is a local
  source drop and stays untracked. A deterministic `scripts/build-art.mjs` uses
  the already-resolved Sharp dependency to crop/resize into `public/art/`; only
  derivatives, the registry, and the script are committed. The build command
  fails if an expected source is missing; the check command validates committed
  outputs without sources. Both fail on a missing output or an aggregate shipped
  art payload above 3 MB. The local source directory remains intentionally
  untracked without changing the user-owned `.gitignore`.
- **One deliberate registry owns every filename and crop.** No component may
  spell a `/art/...` pathname. `components/art/registry.ts` provides the typed
  semantic keys and public paths; `ArtFrame` owns responsive image loading,
  stable crop, dark scrim, accessible alternate text, and a token-only gradient
  fallback on a missing asset. Today header plus its visible first emotional card
  may be eager; all other art lazy-loads.
- **The supplied 41st image is intentional, not a duplicate accident.**
  `tools-focus-study.png` becomes the Tools Focus bento crop; the additional
  `tools-focus-desktop.png` is the expanded Focus-sheet scene. The source
  `money-ledger-with-protagonist.png` is center-cropped as the documented
  `tools.afford` scene. All other source aliases normalize to the exact semantic
  names from `ASSETS.md` (including the supplied `habbit-*`, `health-strech`,
  and `health-weight` spellings) at build time.
- **F11 stays repository-backed and keyless.** Every repaired route calls
  `getSession()` and uses its already-bound repositories; no client sends a
  `userId`. Text, voice, photo, Focus, and Meditation retain their existing
  typed/explicit commit services. Estimates still cannot write without card
  acceptance; all units remain integers; the fake stack stays network-free.
- **No silent fallback semantics.** A required seam that cannot read its scoped
  data renders the screen's documented honest empty state, not seed-like
  invented values. A missing image falls back only visually; it never changes
  route data, action availability, or capture state.
- **Do not touch `.gitignore`.** It is a user-owned working-tree change. Keep it
  unstaged and uncommitted.

## Art delivery contract

### Derivatives

| Set | Output | Crop / target |
|---|---|---|
| Today headers | `public/art/today/{dawn,day,dusk,night}.webp` | 3:1, 1536×512 |
| Domain / plan scenes | `public/art/{habits,health,skills,money}/*.webp` | 16:9, 960×540 |
| Tools | `public/art/tools/{focus,focus-detail,meditation,afford,workout}.webp` | 4:5, 720×900 |
| Onboarding | `public/art/onboard/{welcome,core,generate,confirm}.webp` | 9:16, 720×1280 |
| Milestones | `public/art/mile/{arc-complete,week-back,levelup,first-week,hundred-hours}.webp` | 16:9, 960×540 |
| Coach / Today states | `public/art/coach/week-band.webp`, `public/art/today/{rest,done-evening}.webp` | 6:1, 1440×240; 16:9, 960×540 |

Use WebP with a consistent quality/effort setting, then enforce the actual
aggregate ≤3 MB output gate rather than assuming a quality number meets it.
Preserve the centre/middle band for all manual cover crops; visual review is the
final authority if a supplied composition needs a named per-asset crop position.

### Placement map

- **Today:** local time selects dawn/day/dusk/night header; a real typed `Next
  up` plan/habit card selects a deterministic matching semantic scene; rest and
  all-done states receive their respective emotional card. Image-backed text has
  a token scrim and does not conceal Done/Skip, `via capture`, or satisfaction
  provenance.
- **Tools:** Focus/Meditation/Afford-it/Workout cards use their documented
  4:5 scenes. Focus's expanded sheet uses `focus-detail`; inactive afford/workout
  actions remain visibly unavailable and write nothing.
- **Onboarding:** welcome, CORE, spine generation, and confirmation/accept use
  the four vertical backdrops behind the existing phase content without changing
  the local-draft/one-atomic-accept rule.
- **Journey and Coach:** real derived milestones choose the matching milestone
  art (arc complete, weekly reflection, level-up, first week, 100 hours); the
  weekly Coach brief uses the thin band. No new timeline data or evidence URL is
  created merely to show art.
- **Domain scene registry:** all 20 archetypes are resolvable by their typed plan
  title/domain mapping for Today contextual cards. Unknown/new titles use a
  stable domain fallback from the same registry; no adjective/AI-generated image
  selection occurs at runtime.

## Build shape

1. **Produce deterministic static art and its single access boundary**
   - Implement `scripts/build-art.mjs` with an explicit manifest from supplied
     source filename to semantic output, dimensions, and crop position. It
     creates directories, strips metadata, writes WebP derivatives, validates all
     expected outputs, reports per-file/total size, and exits non-zero above the
     signed payload budget.
   - Add framework-free `components/art/registry.ts` with exhaustive semantic
     keys, typed lookup helpers, and deterministic title/domain fallback. Add a
     single `ArtFrame` surface that preserves fixed media ratios, uses CSS tokens
     for frame/scrim/fallback, has useful alt text, and supports client-side
     fallback after an asset load error. No component imports source PNGs or
     hardcodes an art path.
   - Add focused tests for manifest completeness, no raw PNG/public source paths,
     deterministic domain fallback, all specified output dimensions, and the
     ≤3 MB gate. Add a `pnpm art:build`/`pnpm art:check` command that works with
     no network.

2. **Stitch the real cross-screen flows without widening writes**
   - Trace F2–F11 against the actual server readers and repair only real dead
     ends: capture opens from every tab; a Today action reframes it to “How'd it
     go?”; capture fan-out refreshes Today and the affected domain; a Stats card
     opens that real domain; avatar Settings returns to the live shell/theme;
     Journey evidence routes to its actual entry/lens; and Coach adaptation
     stays before → after → reason → Keep/Revert.
   - Make the Skills drill’s `Start 50m focus` open the existing Focus sheet with
     its scoped skill/duration pre-set. Completing it uses the existing explicit
     tool command, refreshes the Skills mastery value, and preserves its current
     undo/idempotency semantics.
   - Preserve F3's one rich capture path across text, voice, and photo. Any
     integration repair must call the existing parse/route/typed-commit services;
     it must not mirror proposal state in a page component or create a direct
     per-domain write.

3. **Mount the approved art at emotional, not data, moments**
   - Update Today, Tools, onboarding, Journey, and Coach leaves to consume only
     the semantic registry. Keep existing typed DTO boundaries serializable; add
     an explicit art key/selection to a pure view only where it is derived from
     already-typed screen data.
   - Ensure text remains AA over every scrim in the primary Ember Dark evidence
     state, then spot-check the highest-risk light/dark contrast pair (Ember
     Light and Moss Dark) rather than multiplying every screenshot state by all
     six modes. Art respects `prefers-reduced-motion` (no parallax requirement),
     focus order is unchanged, and no asset introduces a display-only action/dead
     link.
   - Keep Header/capture, lenses, Stats, Settings, proposal cards, receipt/photo
     evidence, and Coach daily reading text-led exactly as they are. Do not add
     generated art to persistent evidence or user content.

4. **Exercise the F11 story and visual evidence**
   - Add deterministic integration tests for: Today Done → capture framing;
     canonical capture fan-out updating Today/satisfied-by; Stats → scoped lens;
     Skills drill → Focus pre-set → typed session → refreshed mastery; Journey
     evidence link; Coach adaptation Keep/Revert; avatar Settings/theme; and
     unavailable Tools paths making no write. Include a test that an estimated
     proposal still has no typed row before acceptance.
   - Extend `scripts/screenshot.mjs` with `SHOTS=stitch` and `SHOTS=art` using
     the populated local SQLite seed. `stitch` follows F11 route/action seams;
     `art` captures each placement family (Today time/state, typed contextual
     card, Tools bento/detail, onboarding phases, Journey markers, Coach band)
     at 390px plus desktop smoke in Ember Dark. Add only targeted Ember Light /
     Moss Dark captures where a scrim or domain-tint contrast is genuinely at
     risk. Save evidence under `.verify/screens/`.
   - Run `pnpm art:build`, focused tests, `pnpm check`, `pnpm build`,
     `git diff --check`, and `.codex/hooks/check-invariants.sh`. Sol runs the
     D-041 screenshot design review: mobile defects block; desktop defects block
     only a functional/major composition regression. Confirm raw sources remain
     excluded and all committed derivative files stay inside the payload gate.

## Acceptance and verification

- **P10 / SAR-018:** “the F11 shot list can be performed in the prototype
  without a dead end.” In the real keyless app this means each F2/F4–F11 hand-off
  begins at a public app route, has an honest state/error path, and reaches its
  intended existing view/action without fake navigation or an unsound write.
- **Art:** all 41 supplied scenes have a semantic registry route; shipped WebP
  output is ≤3 MB; expected crops maintain readable lower-third overlays; Today
  eager-loads only its header plus first visible emotional card; every other
  image is lazy; deletion/missing-file fallback is visually graceful.
- **Safety:** `wrongSilentWrites === 0` continues to hold; no estimate auto-files;
  all mutations retain scoped repositories, typed per-domain commit records,
  integer units, five-minute latest-batch undo, and fake-stack keylessness.
- **No scope drift:** no auth/billing/deployment work, no screen redesign, no
  new persistent tables, no real keys, no raw component tokens, and no update to
  the user-owned `.gitignore`.

## Handoff to Terra

Build order: static-art manifest/conversion + registry/tests → trace and repair
the F2–F11 navigation/action seams → mount semantic art in the five allowed
surface families → integration tests and screenshot jobs → payload/keyless/full
validation. Stop and report if a desired image requires new persistent user
content, an art placement would obscure a data/action/control, an asset fails
the hard quality/readability gates, or an integration seam needs a new product
contract. Those are decisions, not silent implementation changes.
